# Repository instructions

## Databricks feedback

After using Databricks for this repository, append an entry to
`docs/databricks-feedback.md`. Record what you tried, what worked, what failed or was
confusing, and any workaround or follow-up that would improve the next attempt.

Write an entry only for hands-on Databricks work, such as using the CLI, APIs,
workspace UI, jobs, pipelines, SQL warehouses, Lakebase, Model Serving, or Databricks
Apps. Planning or editing local documentation alone does not require an entry.

Use the template in the feedback file. Never include access tokens, passwords,
connection strings, private URLs, customer data, or other secrets. Keep entries short
and concrete. If the work did not reveal any friction, say so rather than inventing
feedback.
